# 取り違えドリル（Confusion Drill）

対応要件: FR-80〜FR-83
実装: `domain/usecases/confusion_pair_finder.dart`, `ui/screens/choice_study_screen.dart`
（4択・スピード・語のつくりと描画も進行も同じ形なので1画面にまとめている）,
単語詳細のカードは `ui/screens/word_detail_screen.dart`

## 1. 狙い

`affect` / `effect` のような「紛らわしい語」のリストは市販の教材にもあるが、
**何を混同するかは人によって違う**。既製のリストを解いても、自分が間違えない組は無駄になる。

encello はすでに `learning_logs.answeredText` に
「4択で選んだ選択肢の文字列」と「スペルで実際に打った文字列」を残している。
ここから **その人が実際に取り違えている組**を割り出せる。追加のデータは要らない。

## 2. 取り違えの検出

`ConfusionPairFinder.find(logs, words)` は純粋関数。誤答ログから組を作る。

### 2.1 4択の誤答から

`mode = choice` かつ `isCorrect = false` のログの `answeredText`（選んだ選択肢の文字列）を、
出題方向に応じて語に逆引きする。

| 方向 | `answeredText` の中身 | 逆引き先 |
|---|---|---|
| `enToJa` | 選んだ日本語訳 | `words.meaning` が完全一致する語 |
| `jaToEn` | 選んだ英単語 | `words.headword` が一致する語 |

逆引きできた語を `confusedWith` として、`(正解の語, 選んだ語)` の組を作る。

### 2.2 スペル／リスニングの誤答から

`answeredText`（打った文字列）を正規化して `words.headword` と突き合わせる。
**別の実在語を打っていた場合だけ**組にする。

- `thought` を問われて `though` と打った → `(thought, though)` の組。
- `apple` を問われて `aple` と打った → 実在語ではないので組にしない。
  これは単なる綴りミスで、語の取り違えではない。

### 2.3 組の成立条件

| 条件 | 理由 |
|---|---|
| 同じ組で誤答が2回以上 | 1回はたまたま。繰り返しているものだけを扱う |
| 直近90日以内の誤答 | 昔の混同を蒸し返さない |
| 両方の語がいまも存在し、除外されていない | 削除・除外された語を出さない |

組は**向きを持たない**。`(affect, effect)` と `(effect, affect)` は同じ組として回数を合算する。
片方向だけ間違えていても、もう片方も怪しい。

## 3. ドリルの形式

2語を必ず**並べて**出す。片方だけを問うと、比べて区別する練習にならない。

```
どっちがどっち？

  「〜に影響を与える」（動詞）

    [ affect ]        [ effect ]

  ─────────────────────────
  ✓ affect（動詞：〜に影響を与える）
  ✗ effect（名詞：影響・効果）
     ※ e- は名詞、a- は動詞、と覚える  ← note があれば表示
```

- 2択（迷わせる相手だけを出す）。3つ以上の語が絡む組は、回数の多い2語から出す。
- 出題は両方向を交互に。`affect` を問う回と `effect` を問う回を必ず対にする。
- 解答後に**両方の語の訳と品詞を並べて**示す。正解だけ見せても区別は身に付かない。
- 語に `confusionNote`（text?）があれば添える。無ければ出さない。機械生成しない。

## 4. 起動導線

| 場所 | 表示 |
|---|---|
| モード選択シート | 「取り違えドリル」（組が1つ以上あるときだけ選択肢に出る） |
| 統計画面 | 「よく取り違える組 N件」カード。行タップで両語の詳細、下部に「まとめて練習」 |
| 単語詳細 | 「取り違えやすい語」セクション（組がある語のみ）。相手の語をチップで表示 |

組が0件のときは、モード選択にもホームにも出さない。
「まだデータが足りません」と空のカードを置かない。

## 5. 学習状態への反映

- 正解 → 出題した語の grade 4。
- 不正解 → **両方の語**の grade 1。取り違えている以上、両方あやふやだから。
- `learning_logs` には出題した語の分だけ記録し、`mode = confusion` とする。
  相手の語の状態更新はログに残さない（解答は1回だから）。

## 6. 組の解消

同じ組で**5回連続で正解**したら、その組を「解消済み」として出題対象から外す。

- `resolved_confusions`（`profileId`, `wordIdA`, `wordIdB`, `resolvedAt`）に記録する。
- 解消後にまた誤答したら、記録を消して組を復活させる。
- 統計画面に「解消した組 N件」を出す。取り違えが減っていることも成果として見せる。

## 7. テスト観点

- 4択の誤答2回で組が成立し、1回では成立しない。
- スペルで実在しない綴りを打った誤答が組にならない。
- スペルで別の実在語を打った誤答が組になる。
- `(A,B)` と `(B,A)` が同じ組として回数合算される。
- 91日前の誤答が組に数えられない。
- 除外された語を含む組が出題されない。
- ドリルで不正解のとき、出題語と相手の語の**両方**の `word_reviews` が grade 1 で更新される。
- 5回連続正解で組が `resolved_confusions` に入り、出題されなくなる。
- 解消後に誤答すると組が復活する。
- 組が0件のときモード選択に「取り違えドリル」が現れない。
