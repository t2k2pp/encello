# 学習リマインダー（Reminders）

対応要件: FR-88〜FR-91
実装: `data/services/notification_service.dart`, `domain/services/reminder_service.dart`（抽象）

## 1. 狙い

ストリークは、思い出さなければ切れる。
学習内容そのものより、**思い出す機会があるかどうか**が継続を左右する。

## 2. 通知の内容

1日1通だけ。指定時刻に、その日まだ目標を達成していない場合に出す。

| 状況 | 本文 |
|---|---|
| 復習がある | 「たろうさん、今日の復習が23語あります」 |
| 復習は無いが未達 | 「たろうさん、今日はまだ学習していません。新しい単語はいかがですか」 |
| ストリークが3日以上続いている | 「たろうさん、7日続いています。今日の復習は23語です」 |

- **プロファイル名を入れる**。1台を複数人で使うため、誰宛かが分からないと機能しない。
- 目標を達成済みの日は通知しない。達成した人に「やれ」と言わない。
- 「ストリークが切れます」のような脅す文言は使わない。

## 3. スケジュールの方式

`flutter_local_notifications` の `zonedSchedule` を、
**`AndroidScheduleMode.inexactAllowWhileIdle`** で使う。

- 1日1回の学習リマインダーに秒単位の正確さは要らない。
  `SCHEDULE_EXACT_ALARM` / `USE_EXACT_ALARM` を要求すると、
  Android 14 以降で追加の権限確認やストア審査の説明が必要になる。数分のずれと引き換えに避ける。
- `matchDateTimeComponents: DateTimeComponents.time` で毎日繰り返す。
- 通知IDはプロファイルごとに固定（`1000 + profileId`）。
  プロファイルを増やしても互いの通知を上書きしない。

### 3.1 予約し直す契機

通知本文には件数が入るため、内容は**予約時点の見込み**になる。
次のタイミングで予約し直し、実際とのずれを最小にする。

| 契機 | 挙動 |
|---|---|
| アプリを開いたとき | 現在のプロファイルの明日以降の通知を作り直す |
| セッションを終えたとき | 同上 |
| 設定で時刻・ON/OFF を変えたとき | 該当プロファイルの通知を取り消して作り直す |
| プロファイルを削除したとき | そのプロファイルの通知を取り消す |

アプリを長期間開かないと件数が古くなる。
**7日先までしか予約しない**（7件を個別に予約する）。それ以降は次回起動時に作り直す。
古い件数の通知を延々と出し続けない。

## 4. 権限

| プラットフォーム | 必要なもの |
|---|---|
| Android 13+ | `POST_NOTIFICATIONS` の実行時許可 |
| iOS | 通知許可（`requestPermissions`） |

- 許可は**起動時に求めない**。設定 > 学習でリマインダーを ON にしようとしたときに初めて求める。
  何のための許可かが分かる場面で聞く。
- 拒否された場合、トグルを ON にせず、
  「通知が許可されていません。端末の設定から許可できます」と1行表示する。
  ON に見せかけて鳴らない状態を作らない。
- 恒久的に拒否されている場合も同じ表示にする。OS 設定を開くところまではしない。

## 5. 設定（設定 > 学習）

```
学習リマインダー                                    [ ON ]
  毎日きまった時刻に、その日の復習をお知らせします。
  目標を達成した日は通知しません。

  時刻            [ 19:00 ]      ← TimePicker
  [ テスト通知を送る ]
```

- 「テスト通知を送る」は5秒後に1通出す。実際に鳴るかを確かめられるようにする。
- プロファイルごとの設定（`profiles.reminderEnabled` / `reminderHour` / `reminderMinute`）。
  兄弟で別の時刻に設定できる。

## 6. 通知のタップ

通知をタップしたら、**その通知のプロファイルに切り替えてから**ホームを開く。
別の人のプロファイルが開いたままだと、そのまま学習して記録が混ざる。

`payload` にプロファイル id を入れ、起動時に読む。
該当プロファイルが削除済みなら、切り替えずに通常起動する。

## 7. 抽象化

`domain/services/reminder_service.dart` にインターフェースを置き、
`data/services/notification_service.dart` で `flutter_local_notifications` を使って実装する。

```dart
abstract class ReminderService {
  Future<bool> hasPermission();
  Future<bool> requestPermission();
  /// profileId の通知を7日分予約し直す。既存は取り消してから。
  Future<void> reschedule(int profileId, ReminderPlan plan);
  Future<void> cancel(int profileId);
  Future<void> sendTest(int profileId, String body);
}
```

テストではフェイクを注入し、予約された内容（時刻・本文・件数）を検証する。
実機の通知に依存したテストを書かない。

## 8. テスト観点

- 目標達成済みの日の通知が予約されない。
- 通知本文にプロファイル名と復習件数が入る。
- 予約が7日分・7件で、8日目が含まれない。
- セッション終了後に予約が作り直され、件数が更新される。
- プロファイル削除でそのプロファイルの通知が取り消される。
- 権限が拒否されたときトグルが ON にならない。
- 通知の `payload` のプロファイルへ切り替えてからホームが開く。
- `payload` のプロファイルが削除済みのとき、切り替えずに通常起動する。
