# 派生語ファミリー（Word Families）

対応要件: FR-76〜FR-79
実装: `data/database/tables/word_families.dart`, `ui/widgets/word_family_card.dart`,
`domain/usecases/family_quiz_builder.dart`

## 1. 狙い

`decide` を知っていても、`decision` `decisive` `decidedly` が出ると別の語に見える。
実際には1つの語族で、**まとめて扱えば実質の語彙が数倍になる**。

英検準2級以上と大学入試では「動詞を名詞形に直す」「空所に適切な品詞の形を入れる」が定番で、
語形変化そのものが直接問われる。

## 2. データ

### 2.1 `word_families`

| 列 | 型 | 説明 |
|---|---|---|
| `id` | int | PK |
| `baseForm` | text | 語族の代表形（`decide`）。UNIQUE |
| `note` | text? | 補足（`-sion 型の名詞化`） |

### 2.2 `words.familyId`

`words` に `familyId`（int?, FK, index）を足す。null = どの語族にも属さない。

- 同じ語族の中に同じ品詞が複数あってよい（`decision`（決定）と `decisiveness`（決断力））。
- 語族に属するのは**綴りが派生関係にある語**に限る。
  意味が近いだけの語（`choose` と `decide`）は語族にしない。それは類義語であって派生語ではない。
- 不規則な派生（`long` → `length`、`strong` → `strength`）も語族にできる。
  綴りの規則ではなく派生関係で判断する。

## 3. 単語詳細での表示（FR-77）

```
語族（decide）
  動詞    decide       決める          ●●●○ 定着
  名詞    decision     決定            ●●○○ 学習中
  形容詞  decisive     決定的な        ○○○○ 未学習
  副詞    decidedly    明らかに        ○○○○ 未学習
```

- 品詞・見出し語・訳・習熟度を並べる。行タップでその語の詳細へ。
- 現在見ている語は `accentSoft` の背景で示す。
- 語族に自分しかいない場合はカードを出さない。
- **未学習の派生語がある場合、「この語族をまとめて学習する」ボタンを出す**。
  押すと語族の全語だけのセッションが始まる。

## 4. 語形変化クイズ（FR-78）

`mode = family`。5番目・6番目の学習モードとして独立させず、
**スペルモードの出題形式の1つ**として組み込む。入力もアプリ内キーボードで行う。

### 4.1 出題

```
decide （決める・動詞）

  名詞形にしなさい

  d e c _ _ _ _ _
```

- 提示: 語族の中で**既習の語**を1つ（`decide`）と、求める品詞（名詞）。
- 答え: その語族の該当品詞の語（`decision`）。
- 判定・フィードバックはスペルモードと同一（`SpellJudge` を再利用。惜しいの扱いも同じ）。

### 4.2 出題条件

`FamilyQuizBuilder` は次を満たす語族だけを対象にする。

| 条件 | 理由 |
|---|---|
| 語族に2語以上ある | 変形の問題が作れない |
| 提示する語が既習（`masteryLevel >= 1`） | 知らない語から変形は作れない |
| 求める品詞の語が語族に1つだけ | 答えが一意に定まらないと採点できない |

求める品詞の語が複数ある語族（`decision` と `decisiveness`）は、この形式では出題しない。
どちらも正解になってしまい、片方を不正解にするのは誤りだから。

### 4.3 学習状態

答えた語（`decision`）の `word_reviews` を更新する。提示した語（`decide`）は更新しない。
問われているのは変形先の語であって、提示語ではない。

## 5. 語族の作り方

- プリセット単語帳の作成時に、派生関係のある語を同じ `familyId` に束ねる。
- 語尾から機械的に候補を出す（`-tion` `-ment` `-ness` `-ive` `-able` `-ly` …）ことはできるが、
  **束ねる判断は人が行う**。`present`（贈り物）と `presentation` は語族だが、
  `patient`（患者・忍耐強い）と `patience` は品詞と意味の対応が単純ではない。
- 語族に入れる語が単語帳に無い場合は、その語自体を単語として追加する。
  語族の穴（`decisive` だけ収録されていない）は、まとめて学習する体験を壊す。

## 6. 統計での見せ方

統計画面の習熟度カードに、切り替えで「語族単位」の内訳を出せるようにする。

```
語単位     未学習 1,204 / 学習中 312 / 定着 180 / マスター 92
語族単位   手つかず 380 / 一部 210 / 全部 64      ← 切替
```

「`decide` は知っているが `decisive` は知らない」語族が見えると、
次に埋めるべき穴がはっきりする。

## 7. アセット形式と投入（実装済み）

語族は語の部品と**同じアセット**（`assets/word_parts.json`）に入れる。
形式と検証は [word_parts.md] §8。

```json
{ "baseForm": "decide", "note": "-sion 型の名詞化",
  "members": ["decide", "decision", "decisive", "decidedly"] }
```

- `members` は**見出し語だけ**で指す。投入時に共有の語（`ownerProfileId IS NULL`）を
  引いて `words.familyId` を書く。
- **1語は1つの語族にしか属せない**（`familyId` が1つしか持てない）。
  検証が「1語が2つの語族に入っている」を不合格にする。
- 語族から外れた語は `familyId` を null に戻す。
  アセットから消えた語族は、所属を外してから行を消す。

### 7.1 束ねた実績

170語族・延べ490語。1語族あたり2〜8語。

**§5 の「語族に入れる語が単語帳に無い場合は、その語自体を単語として追加する」を実行した。**
語族を設計した時点で、単語帳に無い派生語が107語あった
（`action` `agreement` `division` `movement` `understanding` など）。
語族の穴を残すと「まとめて学習する」が成立しないため、全部足した。

| 内訳 | 語数 |
|---|---|
| プール（[wordbooks.md] §3.4）から戻した | 39 |
| 新しく書いた | 63 |
| 見出し語として足さず、紐付け側を落とした | 5（`solo` `sonic` `terrace` `terrestrial` `verbally`） |

戻した39語は §2.2 (a) の作り直しで外れていたもの。
プールの値は `--check-pool` で出荷分とそろっていることを確かめてあるので、
そのままチャンクへ移せた。**プールを残しておいたことがそのまま効いた。**

延べ語数は 6,825 → 6,927 になった。

### 7.2 束ねるときに落としたもの

- 1語だけの語族（`decline`）。カードも出題も成立しない（§3・§4.2）。
- 同じ語が2つの語族に入っていたもの（`memory` が `remember` と `memory` の両方、
  `evaluate` が `value` と `evaluate` の両方）。`familyId` は1つしか持てないので、
  どちらに入れるかを決めた。
- `baseForm` が `members` に無いもの（`signify` → `sign` に直した）。

どれも**検証が見つけた**。目で追うと必ず取りこぼす。

## 8. テスト観点

- 語族に自分しかいない語の詳細に語族カードが出ない。
- 語族カードに自分自身が `accentSoft` で示される。
- `FamilyQuizBuilder` が「求める品詞の語が2つ以上ある語族」を出題対象から外す。
- 提示語が未学習の語族が出題対象から外れる。
- 語形変化クイズの正解時、答えた語の `word_reviews` だけが更新され、提示語は変わらない。
- 判定が `SpellJudge` と同じ結果になる（惜しいの扱いを含む）。
- 語族単位の内訳で、全語がマスターの語族だけが「全部」に数えられる。
