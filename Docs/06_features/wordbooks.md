## 2. データの作り方と品質基準

見出し語の集合そのものは事実の列挙だが、**訳語・例文・発音記号は自分たちで用意する**。
既存の単語帳や辞書の記述をそのまま写さない。

| 項目 | 基準 |
|---|---|
| 見出し語 | 小文字で正規化。句（`a lot of`）は語間を半角スペース1つ |
| 品詞 | 1レコード1品詞。同綴異品詞は別レコード |
| 訳 | その品詞で最も使われる語義から最大3つ。`；` 区切り。語義が離れすぎる場合は品詞を分ける |
| 発音記号 | IPA。米音を既定とする。用意できない語は空にする（推測で書かない） |
| 例文 | その語のレベルで読める語彙だけで構成する。10語以内を目安 |
| 例文和訳 | 直訳ではなく自然な日本語。例文があるなら必ず対で用意する |
| level | 1〜5。単語帳の category と整合させる |

- 例文と発音記号は**空を許容する**。全語に無理やり付けるより、空のまま出す方が正しい
  （UI は例文カードごと非表示にする）。
- 品質が担保できない語は収録しない。語数を目標にして機械生成した訳を入れない。

### 2.1 収録語の選び方（機械検査でしか見つからない壊れ方）

見出し語の選定は「その級・その学年で実際に出る語か」で決める。
語数を先に決めてから埋めると、次の壊れ方をする。**目視では気付けないので数える。**

| 検査 | 見るもの | 不合格の例 |
|---|---|---|
| 頭文字の分布 | 見出し語の頭文字を数える | 辞書を A から順に埋めた単語帳は a/b/c に集中する。`a`+`b`+`c` が全体の半分を超えたら選定をやり直す |
| 例文の機能語 | 例文に冠詞・前置詞・be 動詞が1つも無い文の数 | `Appreciate breadth of knowledge experience.` のような名詞の羅列。1割を超えたら例文を作り直す |
| 和訳の括弧 | 和訳に `（…）` が入っている数 | `meaning` の2つ目の語義を訳文に機械的に入れた跡。自然な日本語ではない |
| level の分布 | チャンクごとの level 内訳 | 上限レベルがチャンクの半分を超えたら、その単語帳の範囲外の語を混ぜている |

`jhs_v1` の頭文字分布（s=195 c=159 p=116 t=103 …）が健全な形の目安。

外部で作ったデータを取り込むときも、この4つを通してから採用を判断する。
形式検証（§3.3）が通ることと、中身が使えることは別。

### 2.2 外部生成の5冊に残っている未解決の問題

`jhs_v1` 以外の5冊は外部環境で生成したデータを取り込んだもの。
例文・和訳・`level` は書き直して形式検証をエラー0にしたが、
**見出し語そのものの選定に手を付けていなかった**。
(a)(b)(f) は解消し、残りは未解決。

#### (a) 頭文字の偏り — §2.1 の1つ目の検査に4冊が不合格（解消済み）

| 単語帳 | 見出し語 | `a`+`b`+`c` の割合 | 判定 |
|---|---|---|---|
| `jhs_v1` | 1,651 | 22% | 合格（健全な形の目安） |
| `eiken_pre2_v1` | 880 | 23% | **選定をやり直して合格**（もとは1,386語で90%） |
| `hs_basic_v1` | 1,206 | 22% | **選定をやり直して合格**（もとは1,238語で57%） |
| `eiken_2_v1` | 1,045 | 22% | **選定をやり直して合格**（もとは1,384語で53%） |
| `toeic_basic_v1` | 1,007 | 24% | 合格 |
| `hs_advanced_v1` | 1,002 | 22% | **選定をやり直して合格**（もとは1,311語で65%） |

辞書を A から順に埋めた形跡。**語数を減らしてでも選定をやり直す**のが正しい。

やり直した手順:

1. 分野で分けたチャンク構成と、そこに入る見出し語の一覧を設計する（`jhs_v1` を手本に）。
   **頭文字順に辞書から拾わない。** 分野ごとに実際に使う語を挙げると、
   結果として a/b/c は 20〜25% に落ち着く。
2. 設計した語のうち**他の単語帳（と §3.4 のプール）に既にあるものはレコードを流用する**。
   例文は `word_examples` が単語帳ごとに持てるので、流用しても他の単語帳と衝突しない。
3. 残りだけを新しく書く。
4. **構成から外れた語は消さずに `tool/wordbooks/pool/` へ退避する**（§3.4）。

| 単語帳 | 状態 | 設計 | 流用 | 新規 | 退避 |
|---|---|---|---|---|---|
| `eiken_pre2_v1` | 完了 | 880 | 775 | 105 | 1,109 |
| `hs_basic_v1` | 完了 | 1,206 | 966 | 240 | 754 |
| `eiken_2_v1` | 完了 | 1,045 | 756 | 289 | 1,104 |
| `hs_advanced_v1` | 完了 | 1,002 | 449 | 553 | 1,088 |

流用率は 88% → 80% → 72% → 45%。冊が難しくなるほど既存5冊に無い語が増える
（`eiken_2_v1` は熟語88語のうち69語を新しく書いた。`hs_advanced_v1` は
`ubiquitous` `paradigm` `jurisdiction` のような難関大の語が他5冊にほとんど無く、
553語を新しく書いた）。

**計画と道具は `tool/wordbooks/plans/` に置いてある**（同ディレクトリの README に手順）。
同じ形の組み直しをするときは、そこから始められる。

#### (b) チャンク名と中身が一致していない — 解消済み

チャンク名は分野を名乗っているのに、中身は頭文字順に切られていて分野で分かれておらず、
`eiken_2_v1/07_adjectives_eval_person` が名詞46・形容詞37 のように
全チャンクで名詞が最多になっていた。

該当した `eiken_pre2_v1` / `eiken_2_v1` / `hs_advanced_v1` は (a) の作り直しで解消した。
**作り直しではチャンク内の品詞をそろえるため、この問題は (a) と同時に片付く。**

#### (c) `partOfSpeech` と `meaning` の不整合

§2 の「1レコード1品詞」に反し、`meaning` に別品詞の語義が混ざっているものがある。
`bear`(verb) に「クマ」、`can`(noun) に「〜できる」、`close`(verb) に「親しい」など。
別レコードに分けるか `meaning` を品詞に合わせるかを、全冊を機械走査してから決める。

#### (d) 見出し語の形と収録の妥当性

- 複数形のまま登録されている: `commercials` `recipients` `blooms` `crises` `cosmetic`
- 固有形容詞なのに小文字: `atlantic`（検証が `a-z` しか許さないため大文字化できない）
- 級の水準を超える語: `arraign` `descant` `condole`（`eiken_2_v1`）
- 学習者向けとして再検討が要る語: `cock`（米語で俗語）、`breast` `belly` `brandy`
- 例文の冠詞欠落が `hs_advanced_v1` に多い
  （`Company disclosed financial reports.` `Search engine uses complex algorithm.` など）。
  (a) の作り直しで流用した449語がこの例文を持ったままなので、**残っている**
- 訳語の取り違え: `idiocrasy`「愚民政治」（正しくは特異体質）、
  `cannibal`「食肉動物」（`carnivore` と混同）、`arguably`「間違いなく」（意味が反転）
- 助動詞・限定詞の区分が `partOfSpeech` に無く、`can` `will` が `verb`、
  `a` `the` `some` が `adjective` になっている（`jhs_v1`）

#### (e) `note` の語数と実語数が合わない

`toeic_basic_v1` は全チャンクの `note` が「(90語)」だが、実語数は 82〜98 でばらついている。

#### (f) 単語帳をまたぐ `meaning` / `level` の食い違い — 解消済み

同じ `(headword, partOfSpeech)` が2冊以上に入っている語が1,700あり、
`meaning` が1,177、`level` が802、`phonetic` が155で食い違っていた。
これらは `words` に1つしか入らないため、最後に投入した単語帳の値で上書きされていた。

原因は **`level` が単語帳ごとの相対尺度で付けられていたこと**。
`altruism` が `hs_basic_v1` で 2、`hs_advanced_v1` と `eiken_2_v1` で 4 という状態で、
「やさしい単語帳を正とする」と 2 に、「最大を採る」と `trip` `box` のような中学語が
押し上げられる。どちらの機械規則でも間違うため、判断で決め直した。

**level は全単語帳を通した絶対難易度**として付け直した。

| level | 位置づけ | 例 |
|---|---|---|
| 1 | 中学1〜2年で習う最基本語 | `apple` `run` `big` |
| 2 | 中学3年〜高校入学時 | `arrive` `decide` `improve` |
| 3 | 高校基礎〜英検準2級 | `recommend` `apply` `opportunity` |
| 4 | 高校応用〜英検2級・大学入試 | `assume` `negotiate` `comprehensive` |
| 5 | 英検準1級以上・専門的で低頻度 | `inherent` `arbitrary` `arraign` |

`meaning` は**収録しているすべての単語帳で通用する訳**にした。
`degree` は `jhs_v1` の例文が「温度の度」、`eiken_2_v1` が「学位」なので、
両方を含む `学位；度；程度` にする。狭い訳を選ぶと上位の単語帳で語義が足りなくなる。

`levelRange` は絶対尺度になったことで、その単語帳が実際にまたぐ範囲を表すだけの
記述的な値になった。範囲外の語を弾く役目は §2.1 の分布の検査が担う。

崩れを防ぐため、§3.3 の検証に「単語帳をまたぐ不一致」を足した（`--check-all`）。

#### (g) `meaning` の丸括弧

全冊で 102 件（例: `acre`「エーカー（面積単位）」）。
検証エラーにはならないが、`exampleJa` で丸括弧を禁じている規則と揃っていない。

## 3. アセット形式と投入

`assets/wordbooks/<presetId>.json`。

```json
{
  "presetId": "jhs_v1",
  "name": "中学英単語",
  "emoji": "🏫",
  "category": "juniorHigh",
  "colorSeed": 1,
  "seedVersion": 4,
  "bandSize": 1600,
  "sortOrder": 10,
  "note": "中学校で学ぶ基本語彙",
  "words": [
    {
      "presetId": "jhs_v1:apple:noun",
      "headword": "apple",
      "partOfSpeech": "noun",
      "phonetic": "/ˈæpəl/",
      "meaning": "りんご",
      "exampleEn": "I ate an apple for breakfast.",
      "exampleJa": "朝食にりんごを食べました。",
      "level": 1
    }
  ]
}
```

| 項目 | 意味 |
|---|---|
| `colorSeed` | 識別色の割当シード（`AppColors.seedColor`）。一覧サムネと単語帳チップに使う |
| `bandSize` | 語彙力測定で帯として使うときの語数。帯に使わない単語帳は `null` |
| `sortOrder` | 単語帳一覧の並び。帯として使う単語帳は易→難の順に並べる |
| `phonetic` / `exampleEn` / `exampleJa` | 空文字は「値なし」として `null` で取り込む（空文字と null を DB で混在させない） |

読み込むアセットは `SeedImporter.assetPaths` に**明示列挙する**。アセット一覧の走査にしない
（列挙漏れは投入されないことですぐ気付けるが、走査だと意図しないファイルが混ざっても気付けない）。
並びは `sortOrder`（易→難）に合わせる。§1 の6冊すべてを列挙している。

読むアセットはコンストラクタの `paths` で差し替えられる。テストが1冊だけを投入して
差分適用のふるまいを確かめられるようにするため（同梱冊数が増えても差分適用のテストが壊れない）。

### 3.1 投入の手順（`SeedImporter`）

起動ゲート（[02_architecture.md] §4）で実行する。

1. `SharedPreferences` の `seed.installedVersion` と、アセット側の最大 `seedVersion` を比べる。
2. 同じなら何もしない。
3. 新しければ、単語帳ごとに次を1トランザクションで行う。
   - `wordbooks` を `presetId` で upsert（`name` / `emoji` / `note` / `seedVersion` を更新）。
   - `words` を `(headword, partOfSpeech)` で upsert。ただし **`isEdited = true` の語は上書きしない**
     （ユーザーの編集を消さない）。
   - `word_examples` を `(wordId, sourcePresetId)` で upsert（[03_data_model.md] §2.4）。
     **`sourcePresetId` は投入中の単語帳の `presetId`**。
     こうしないと、同じ語を複数の単語帳が持つとき、最後に投入した単語帳の例文で上書きされる。
   - `wordbook_entries` を差し替える。アセットから消えた語は所属だけを外し、
     `words` の行と `word_reviews` は残す（学習履歴を消さない）。
4. 全部成功したら `seed.installedVersion` を更新する。

- 失敗したらトランザクションを巻き戻し、起動ゲートにエラーと再試行を出す。
  空の単語帳でアプリを起動させない。**全単語帳を1つのトランザクションで適用する**
  （半分だけ入った状態を残さない）。
- 判定は**アセット側の最大 `seedVersion`** と `seed.installedVersion` の比較だけで行う。
  よって**単語帳を1冊追加するときも `seedVersion` を上げる**。上げないと、
  すでに投入済みの端末に新しい単語帳が入らない。
  **見出し語の入れ替え（§2.2 (a) の作り直し）も同じ**で、上げなければ
  投入済みの端末は古い見出し語のまま。`eiken_2_v1` の作り直しは上げ忘れていたため、
  `hs_advanced_v1` の作り直しと合わせて 3 → 4 に上げた。
- **6冊の `seedVersion` は常に同じ値にそろえる**（現在は 4）。
  判定が最大値だけを見るため、冊ごとに版がずれていると
  「版の小さい冊を足しても最大が動かず、その冊が端末に届かない」という壊れ方をする。
  実際 M8-A で `jhs_v1` だけを 2 に上げ、M8-B で残り5冊を 1 のまま足したため、
  `jhs_v1` を投入済みの端末に5冊が入らない状態になっていた。
  そろっていることは `test/data/preset_wordbook_asset_test.dart` が確かめる。
  版を上げるときは6冊まとめて上げる。
- 初回は全単語帳を投入するが、**学習対象としては選択しない**。
  ホームの初回表示で「学習する単語帳を選びましょう」を出し、
  語彙力測定でレベルに合う1冊を提案するか、自分で選ばせる（[04_screens_and_flows.md] §4.1）。
- 学習対象の選択は学習者ごと（`profiles.selectedWordbookIds`）。
  投入は端末に1回だけで、学習者を増やしても再投入しない。

### 3.2 プリセット語の編集と復帰

- ユーザーがプリセット語を編集すると `isEdited = true` になり、一覧・詳細に「編集済み」バッジが付く。
- 詳細の「元に戻す」は、`words.presetId` をキーにアセットを引き直して値を戻し、`isEdited = false` にする。
  編集前の値を DB に二重保存しない（アセットは常に同梱されている）。
- アセットに該当 `presetId` が無い場合（プリセットの改版で語が消えた）は「元に戻す」を出さない。

### 3.3 アセットの作り方（分割ソースとビルド）

1冊は1,000語を超える。1つの JSON を継ぎ足しで育てると、重複・書式のぶれ・
壊れた JSON に気付けないまま出荷することになる。
そこで**分野ごとの分割ソースを人が書き、ビルドツールが検証して1本に結合する**。

```
tool/wordbooks/src/<presetId>/_book.json      単語帳のメタ + 収録チャンクの列挙
tool/wordbooks/src/<presetId>/NN_<slug>.json  チャンク1本（分野ごと・90語程度）
tool/wordbooks/allowed_example_words.txt      例文に出てよい語（不規則活用・固有名詞）
        ↓  dart run tool/build_wordbooks.dart
assets/wordbooks/<presetId>.json              出荷するアセット（手で編集しない）
```

- 収録するチャンクは `_book.json` の `chunks` に**明示列挙する**（`assetPaths` と同じ理由）。
- `words[].presetId` は**ビルドが生成する**（`<presetId>:<headword>:<partOfSpeech>`）。
  手書きさせると綴り違いが混ざり、「元に戻す」（§3.2）がアセットを引けなくなる。
- 検証で `error` が1件でも出た単語帳は書き出さない。半分だけ直ったアセットを出荷しない。

検証の内容（`tool/wordbook_validator.dart`）。

| 不合格（error） | 警告（warning） |
|---|---|
| 見出し語に使えない文字 / 品詞が不正 / 複数語なのに `phrase` でない | 発音記号がない |
| `(headword, partOfSpeech)` の重複 | 例文に見出し語が見当たらない |
| 訳が空・日本語なし・語義が4つ以上・半角 `;` | 例文が10語超（12語超は不合格） |
| 発音記号が `/` で囲まれていない / 句に発音記号がある | 例文にこの単語帳の外の語がある |
| 例文と和訳が対になっていない / 例文が他の語と同一 | |
| 例文の終止符・和訳の日本語 / `level` が範囲外 | |
| 同じ `(headword, partOfSpeech)` が単語帳をまたいで `meaning` / `phonetic` / `level` が違う | |

最後の1つは全単語帳をまとめて検査する（`--check-all`）。
`meaning` `phonetic` `level` は語の属性で `words` に1つしか入らないため、
単語帳ごとに違う値を書くと、最後に投入した単語帳の値で上書きされる
（[03_data_model.md] §2.3・§2.4）。例文だけは単語帳ごとに違ってよい。

「例文にこの単語帳の外の語がある」は、見出し語（と機械的に広げた活用形）＋
`allowed_example_words.txt` に無い語を挙げる。
**例文をその単語帳の語彙で書けているかの目安**で、不合格にはしない
（機械的な活用の展開で全部は拾えないため）。

書くときの規則と警告の扱いは `tool/wordbooks/README.md`。
出荷したアセットが規則を満たしていることは `test/data/preset_wordbook_asset_test.dart`
が同じ検証ロジックで確かめる（ビルドを通さずにアセットだけ直しても気付ける）。

### 3.4 語のプール（`tool/wordbooks/pool/`）

単語帳の構成を組み直すと、収録から外れる語が出る。**外した語は消さずにここへ置く。**

```
tool/wordbooks/pool/<presetId>_dropped.json
```

- 形式は**チャンクファイルと同じ**（`chunk` / `note` / `words`）。
  そのため `_book.json` の `chunks` に足すだけで、そのまま単語帳へ戻せる。
- **ビルドの対象外**。アセットには入らないので、出荷サイズにも起動時の投入にも影響しない。
- 外す語は「覚えなくてよい語」ではなく「その単語帳の構成に合わなかった語」。
  訳・例文・発音記号は作り込んだあとなので、捨てると同じ作業をやり直すことになる。
  将来この材料から別の単語帳を組む（辞書に近い語彙まで扱う）ときの元になる。
- 現状（いずれも §2.2 (a) の作り直しで外したもの）:
  `eiken_pre2_v1_dropped.json` に1,109語、`hs_basic_v1_dropped.json` に754語、
  `eiken_2_v1_dropped.json` に1,104語、`hs_advanced_v1_dropped.json` に1,088語。
- **プールは次の作り直しの材料になる。** 作り直しは流用元としてプールも見るため
  （`hs_basic_v1` の1,206語のうち一部は `eiken_pre2_v1` のプールから戻したもの）、
  ここに残しておくほど後の冊で新しく書く語が減る。

## 4. ユーザー単語帳

- 追加は SCR-12 の FAB から。名前・絵文字・識別色・category（`custom` 固定）を入力する。
- ユーザー単語帳は**全学習者で共有**する（マイ単語帳だけが個人のもの。[my_words.md] §2）。
  兄が作った単語帳を弟も学習対象に選べる。
- 単語の追加は SCR-13 から。見出し語と品詞の組が既存の共有語と一致する場合は、
  新規作成せず**既存の単語をこの単語帳に所属させる**（学習状態を分けないため）。
  その旨をシートに1行表示する（「この語はすでに『中学英単語』にあります。学習状態は共有されます」）。
- 削除できるのは `source != preset` かつマイ単語帳でない単語帳だけ。
  削除は所属（`wordbook_entries`）だけを消し、`words` と `word_reviews` は残す。
  他の単語帳にも属している可能性があるため。
  どの単語帳にも属さなくなった単語は、設定 > データの「未所属の単語を整理」で手動削除する
  （自動では消さない）。
- 削除する単語帳を学習対象にしている学習者がいる場合、
  確認ダイアログにその人数を出す（「じろうさんが学習対象にしています」）。

## 5. CSV インポート

対応要件: FR-07

- 列: `headword,partOfSpeech,phonetic,meaning,exampleEn,exampleJa,level`。
  ヘッダ行の有無を自動判定せず、**インポート画面で「1行目はヘッダ」のチェックを明示させる**。
- 取り込み前にプレビュー（先頭20行）と、列の対応（どの列がどのフィールドか）を確認させる。
- 検証で弾く行と理由を、行番号付きの一覧で示す。

| 弾く条件 | 理由の表示 |
|---|---|
| `headword` が空 | 「見出し語がありません」 |
| `headword` に英字以外（スペース・ハイフン・アポストロフィ以外）が含まれる | 「英単語として扱えない文字が含まれます」 |
| `partOfSpeech` が定義済みの値でない | 「品詞が不正です: xxx」 |
| `meaning` が空 | 「日本語訳がありません」 |
| `level` が 1〜5 でない | 「レベルは1〜5で指定してください」 |
| 同一ファイル内で `(headword, partOfSpeech)` が重複 | 「N行目と重複しています」 |

- 弾いた行は取り込まない。推測で補完しない。
- 有効な行だけを取り込むか、全部やめるかをユーザーに選ばせる。
- 文字コードは UTF-8 と Shift_JIS を判定して読む。判定できない場合は取り込まず、
  「文字コードを判別できません。UTF-8 で保存し直してください」と示す。

## 6. 学習対象の選択

- SCR-12 の各行にある `Switch` で選ぶ。複数選択できる（FR-04）。
- 選択は `profiles.selectedWordbookIds` に永続化する。**学習者ごとに別**。
- 1冊も選ばれていない状態を許容する。その場合ホームは初回表示と同じ案内を出し、
  勝手にどれかを選んだことにしない。
- マイ単語帳は既定で選択済みにする（自分で登録した語はすぐ学習したいはずのため）。

## 7. テスト観点

- 出荷するアセット（`assets/wordbooks/*.json`）は6冊すべてに §3.3 の検証を当てる
  （`test/data/preset_wordbook_asset_test.dart`）。ビルドを通さずにアセットを直接触った場合にも気付ける。
- `SeedImporter`: 同梱プリセットが6冊すべて読めて投入できる。
- `SeedImporter`: 同じ `seedVersion` で2回実行しても行が増えない（冪等）。
- `isEdited = true` の語がプリセット再投入で上書きされない。
- アセットから消えた語の `wordbook_entries` は外れるが `word_reviews` は残る。
- 投入の途中で失敗したらすべて巻き戻る。
- 既存語と同じ `(headword, partOfSpeech)` をユーザー単語帳に追加すると、
  行が増えずに `wordbook_entries` だけが増える。
- CSV: 各不正パターンが正しい理由で弾かれ、有効行だけが取り込まれる。
- Shift_JIS の CSV が正しく読める。判別不能なバイト列は取り込まれない。
